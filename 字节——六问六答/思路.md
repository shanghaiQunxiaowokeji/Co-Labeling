# 六问六答数据集生成思路

原则（承 README）：大模型流程是**提示 —— 扩增 —— 标注（剪枝）**，过多的任务性提示词是幻觉主因。所以**任务要求写短，术语与资料源写密**，偏差交给 harness 后剪枝，不在对话里纠正模型。

---

## 一、特异化提示词

一份提示词只服务一个方向，删掉与当前题目无关的领域信息。

- 删非互联网方向的示例、类目、术语。
- 删评价性、纠正性措辞，只写该做什么。
- 内部词（第一轮、出题、考核、评测）只留在后台规则，不进题面。

---

## 二、扩展核心提示词

腾出来的空间用于提高信息密度，加厚两块：

- **触达器：产品经理的工作内容**：权限、登录、通知、账号、搜索推荐、会员订单、内容发布、接口升级、需求梳理、改版排期、指标设计、风险评审；以及排期 / 人日 / SLA / 版本边界这几类数字，和评审稿、比较表、排期、风险矩阵、CSV / JSON 等交付形态。这些词是**触达器**。
- **触达器：资料源**：限定政府采购网、公共资源交易中心、央国企采购平台。

---

## 三、RAG 构建
从稀疏的原材料中，提取出核心的限制。使得材料后续生成中，不会因为无关词汇产生**注意力偏移**

先读原文再出题。三份材料分工互补（功能范围 / 工期与指标 / 实施与验收），逐项抽出类目、阈值、期限、数据，连同原文位置记成固定字段的硬条件表。
---

## 四、结构化输出，保持注意力集中，并使得结论符合提交要求

在结构化输出时，要求明文输出从RAG中提取得到的核心信息，使得其注意力集中到核心有效Token上

七栏固定顺序，附件与硬条件排在题目之前——证据先于题目，模型写题时只能在自己刚抄出来的 Token 上展开。要求 1–6 手写编号、与正文同段，保证整段复制即可直接发问。
